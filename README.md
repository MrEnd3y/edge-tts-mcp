# edge-tts-mcp

Асинхронный MCP-сервер синтеза речи Microsoft Edge с транспортом stdio.
Создаёт MP3, OGG/Opus, субтитры SRT/WebVTT и JSON с таймингами слов.
Возвращает локальные пути к файлам. Воспроизведение, отправку и загрузку выполняет клиент.

## Требования

- Python **3.12+**.
- Доступ к сервису Microsoft: синтез выполняется онлайн, текст передаётся сервису.
- Для OGG/Opus — FFmpeg с `libopus`.
- Для подгонки длительности — FFmpeg и FFprobe.

Обычный MP3, субтитры и тайминги не требуют FFmpeg.

## Установка и запуск

Через `uvx`:

```sh
uvx --from git+https://github.com/MrEnd3y/edge-tts-mcp.git edge-tts-mcp
```

Установка из локальной копии репозитория:

```sh
python -m pip install .
edge-tts-mcp
```

`uvx` устанавливает Python-зависимости, но не системные FFmpeg/FFprobe.

## Подключение MCP

Пример конфигурации клиента:

```json
{
  "mcpServers": {
    "edge-tts-mcp": {
      "command": "uvx",
      "args": [
        "--from",
        "git+https://github.com/MrEnd3y/edge-tts-mcp.git",
        "edge-tts-mcp"
      ]
    }
  }
}
```

Для установленного пакета используйте `"command": "edge-tts-mcp"` без аргументов.
Настройки передаются через `env`; при необходимости укажите абсолютный путь к команде.
MCP-клиент запускает сервер как дочерний процесс и работает с его stdin/stdout.
Таймаут MCP-клиента должен быть больше таймаута инструмента, например 60 секунд
при стандартном лимите синтеза 45 секунд.

## Инструменты

### `get_capabilities()`

Возвращает форматы, наличие исполняемых FFmpeg/FFprobe, ограничения, настройки голоса,
профили и доступность субтитров и таймингов. Сетевых запросов не делает.
Наличие FFmpeg не гарантирует поддержку libopus.

### `list_voice`

Без аргументов возвращает все голоса. `locale` фильтрует по префиксу без учёта
регистра (`ru`, `ru-RU`, `en`), `gender` принимает `Female`, `Male` или пустую строку.
`query` ищет по метаданным, `offset` и `limit` задают страницу результатов.
Поле `ShortName` из ответа передаётся в `tts.voice`.
Сетевой запрос ограничен 30 секундами; ошибка не маскируется пустым списком.

### `tts`

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `text` | обязательный | Непустой текст, до 100000 символов |
| `voice` | настройка сервера | Изначально `ru-RU-SvetlanaNeural` |
| `rate` | настройка или профиль | Скорость, например `+15%` |
| `volume` | настройка или профиль | Громкость, например `-10%` |
| `pitch` | настройка или профиль | Высота, например `+5Hz` |
| `audio_format` | `mp3` | `mp3` или `ogg` |
| `subtitles` | `none` | `none`, `srt` или `vtt` |
| `word_timings` | `false` | Сохранять JSON с таймингами слов |
| `profile` | `default` | `default`, `narration`, `notification`, `slow` |
| `timeout` | ENV или `45` | Бюджет выполнения: больше 0, не больше 300 секунд |
| `max_audio_duration_seconds` | ENV или `300` | Предел длины готового клипа: конечное число секунд > 0, независимо от `timeout` |
| `target_duration_seconds` | `null` | Желаемая длина клипа: конечное число > 0, не больше `max_audio_duration_seconds` |
| `tempo_min` | ENV или `0.5` | Минимальный допустимый темп подгонки, число от 0.5 до 2.0 |
| `tempo_max` | ENV или `2.0` | Максимальный допустимый темп подгонки, число от 0.5 до 2.0; не меньше `tempo_min` |

**Обычное аудио:**

```json
{"text": "Привет! Проверка синтеза речи."}
```

**OGG/Opus с субтитрами и таймингами:**

```json
{"text": "Привет, мир!", "audio_format": "ogg", "subtitles": "vtt", "word_timings": true}
```

### Подгонка длительности

```json
{"text": "Привет, мир!", "target_duration_seconds": 1.5, "tempo_min": 0.8, "tempo_max": 1.25, "subtitles": "srt", "word_timings": true}
```

Без цели или с `null` подгонка не выполняется: `tempo_min`/`tempo_max`
не меняют скорость, FFprobe не вызывается и поля подгонки не добавляются в ответ.
Независимый предел `max_audio_duration_seconds` действует и без цели.

После синтеза измеряется исходный MP3 и вычисляется `tempo = source_duration / target_duration`.
FFmpeg `atempo` изменяет скорость без обрезки речи и добавления тишины.
Диапазон по умолчанию и абсолютные технические пределы — **0,5–2,0**.
В запросе или ENV можно задать свой диапазон в этих пределах, например 0,85–1,15.
Границы должны быть конечными числами: `0.5 <= tempo_min <= tempo_max <= 2.0`.
Сервер не расширяет их автоматически.

Если требуемый темп вне выбранного диапазона, возвращается `success: false`,
`error_code: "target_duration_unreachable"` и поля `required_tempo`, `tempo_min`,
`tempo_max`, `source_duration`, `target_duration` (длительности в секундах), без аудиофайла.
Клиент может повторить запрос с другими допустимыми границами.
Если отношение переполняется, `required_tempo` равен `null` (цель всё равно недостижима).
Готовый файл проверяется **FFprobe** с допуском **max(0,05 секунды, 1% цели)**.
При темпе 1,0 MP3 не перекодируется, но итоговая длительность всё равно проверяется.
Если допуск не достигнут, аудио возвращается с `target_met: false` и предупреждением.
Это лишь подгонка длительности клипа в заданных пределах, а не гарантия
естественной речи, идеальной синхронизации или точного выравнивания отдельных слов.

### Ответ и предупреждения

Успешный ответ содержит `success: true`, `path` и `audio_path`, `size`,
`duration_seconds`, `format`, `mime_type`. Длительность относится к готовому файлу
и округляется до миллисекунд.

- С субтитрами: `subtitle_path`, `subtitle_format`.
- С таймингами: `word_timings_path`, `word_count`.
- С целью: `tempo` — фактически применённый темп, и объект `duration_fitting`.

Поля `duration_fitting`:
`target_duration_seconds`, `original_duration_seconds`, `requested_tempo`,
`applied_tempo`, `processed`, `tempo_min`, `tempo_max`,
`actual_duration_seconds`, `tolerance_seconds`, `target_met`.

`tempo` совпадает с `applied_tempo`; 1,0 означает отсутствие изменения скорости.
**`success: true` не гарантирует достижения цели**: проверяйте
`duration_fitting.target_met` и `warnings` (`duration_target_not_met`, `duration_mismatch`).
При ошибке обработки или невалидном результате возвращается исходная речь
с предупреждением, если её удалось сохранить в запрошенном формате.
Отсутствие необходимого FFmpeg/FFprobe возвращает понятную `audio_error`.
Если проверить длительность возвращаемого файла не удалось, запрос завершается
ошибкой `audio_error`, а не сообщает об успешной подгонке.

### Тайминги и субтитры

Источник таймингов — события Microsoft WordBoundary, не распознавание или
принудительное выравнивание. JSON содержит объекты вида
`{"word": "Привет", "start_ms": 100, "end_ms": 500}`.

После изменения скорости времена пересчитываются как `round(old_time_ms / tempo)`;
SRT/VTT формируются по пересчитанным данным. Если события отсутствуют, некорректны
или выходят за границы клипа, sidecar-файлы не создаются; аудио возвращается
с предупреждением `timing_metadata_unavailable`. Выдуманные тайминги не подставляются.
Слова группируются в короткие фразы; субтитры сохраняются отдельным файлом.

### Ограничения

Подгонка и FFprobe входят в общий `timeout`, но он не ограничивает длину клипа.
Например, `timeout=60` и `max_audio_duration_seconds=600` означают максимум минуту
на выполнение и максимум десять минут готового аудио. Обработка может не успеть
за минуту. Предел цели определяется `max_audio_duration_seconds`, а не таймаутом.
Если готовый файл превышает предел, возвращается `audio_duration_exceeded`
без публикации файлов. Речь не обрезается. Предел проверяется и без цели.

Профиль `default` использует настройки сервера. `narration` задаёт скорость `-10%`,
`notification` — `+15%`, `slow` — `-25%`, с нейтральной громкостью и высотой.
Явные параметры вызова перекрывают профиль. Профили не меняют голос и не задают эмоции.

Таймаут включает очередь, синтез, обработку и запись результатов.
Длинный текст разбивается библиотекой на части со сквозными смещениями;
лимит 100000 символов не гарантирует завершения за 300 секунд.

Ошибки возвращают `success: false`, `error_code` и `error`.
Коды: `invalid_input`, `timeout`, `no_audio`, `audio_error`, `io_error`,
`service_error`, `feature_disabled`, `target_duration_unreachable`, `audio_duration_exceeded`.
Нарушение MCP-схемы аргументов возвращается как ошибка инструмента.

## Настройки

| Переменная окружения | По умолчанию | Аргумент CLI |
| --- | --- | --- |
| `EDGE_TTS_OUTPUT_DIR` | `~/.edge-tts-mcp/output` | `--output-dir` |
| `EDGE_TTS_FFMPEG` | `ffmpeg` в PATH | `--ffmpeg` |
| `EDGE_TTS_FFPROBE` | `ffprobe` в PATH | `--ffprobe` |
| `EDGE_TTS_TEMPO_MIN` | `0.5` | — |
| `EDGE_TTS_TEMPO_MAX` | `2.0` | — |
| `EDGE_TTS_TIMEOUT_SECONDS` | `45` | — |
| `EDGE_TTS_MAX_AUDIO_DURATION_SECONDS` | `300` | — |
| `EDGE_TTS_VOICE` | `ru-RU-SvetlanaNeural` | `--voice` |
| `EDGE_TTS_RATE` | `+0%` | — |
| `EDGE_TTS_VOLUME` | `+0%` | — |
| `EDGE_TTS_PITCH` | `+0Hz` | — |
| `EDGE_TTS_ALLOW_SIDECARS` | `1` | `--disable-sidecars` запрещает субтитры/тайминги |
| `EDGE_TTS_MAX_CONCURRENT` | `2`, диапазон 1–16 | `--max-concurrent` |

Настройки читает и проверяет `edge_tts_mcp/config.py` при запуске.
Для индивидуальных настроек приоритет: **параметры MCP → ENV → встроенные значения**.
Пропуск границы темпа наследует её из ENV независимо от другой границы;
получившаяся пара всё равно должна удовлетворять `min <= max`.
`get_capabilities` показывает эффективные значения по умолчанию; числовые
значения также отражаются в MCP-схеме.
ENV задаёт значения по умолчанию, а не отдельные режимы работы.
Абсолютные границы темпа 0,5–2,0 заданы в коде и не расширяются через ENV или MCP.

Директория сохранения, исполняемые файлы, разрешение sidecar-файлов и параллелизм —
серверные настройки, не аргументы `tts`. CLI переопределяет соответствующие ENV.
Сервер не требует `.env` и не загружает его автоматически. Обычно значения
передаются через `env` в конфигурации MCP-клиента. `.env.example` содержит шаблон.
При запуске из репозитория файл можно явно загрузить через uv:

```sh
uv run --env-file .env python -m edge_tts_mcp
```

Булевы настройки принимают `1/0`, `true/false`, `yes/no`, `on/off`.
Неверные настройки останавливают запуск с кодом 2 и понятной ошибкой в stderr
без значения переменной и без traceback. Наличие FFmpeg/FFprobe проверяется
только для операций, которым они необходимы, а не при старте.

Готовые файлы остаются до удаления пользователем. Временные файлы удаляются
при завершении, ошибке или отмене запроса.
Каждый файл публикуется атомарно; набор файлов не является транзакцией
при аварийном завершении процесса. Новые каталоги на POSIX создаются с правами
`0700`, готовые файлы — `0600`; на Windows действуют наследуемые ACL.

## Docker

Из корня репозитория:

```sh
docker compose build
docker compose run --rm -T edge-tts-mcp
```

Без Compose:

```sh
docker build -t edge-tts-mcp:local .
docker run --rm --init -i -v speech-output:/data/output edge-tts-mcp:local
```

Контейнер содержит FFmpeg и FFprobe и работает от непривилегированного пользователя.
Сетевые порты не используются. MCP-клиент подключается к stdin/stdout процесса:
для Compose нужен `run --rm -T`, а не `up -d`; для `docker run` — `-i` без `-t`.

Compose берёт настройки из окружения и необязательного `.env`, передавая только
переменные, перечисленные в `compose.yaml`. Окружение имеет приоритет над файлом.
Незаданные значения получают defaults; явно пустые проходят проверку сервером.
Отдельный файл можно выбрать через `docker compose --env-file tts.env run --rm -T edge-tts-mcp`.

В Compose каталог вывода фиксирован: **`/data/output`**, том — `speech-output`.
`EDGE_TTS_OUTPUT_DIR` хоста не меняет этот путь. Для доступа к файлам с хоста
замените том на bind mount `путь_на_хосте:/data/output` и обеспечьте права записи
пользователю контейнера. При сборке UID/GID можно задать через `APP_UID`/`APP_GID`.
Возвращаемые пути относятся к контейнеру; клиент должен учитывать это при доставке файлов.

Переопределения `EDGE_TTS_FFMPEG`/`EDGE_TTS_FFPROBE` должны указывать на исполняемые
файлы внутри контейнера, а не на хосте. На Windows для запуска Compose из MCP-клиента
может потребоваться наследование `ProgramFiles`, чтобы Docker нашёл плагин Compose.

## Разработка

```sh
uv sync --group dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run bandit -q -r edge_tts_mcp
```

По умолчанию тесты не обращаются к Microsoft и не требуют Docker.
Тестовый FFmpeg входит в dev-зависимости; FFprobe нужен в PATH или через `EDGE_TTS_FFPROBE`.
Если его нет, интеграционные проверки подгонки пропускаются.

Дополнительные проверки включаются переменными окружения:

| Переменная | Проверки | Требования |
| --- | --- | --- |
| `EDGE_TTS_LIVE_TESTS=1` | Реальный синтез Microsoft | Сеть; для подгонки — локальный FFprobe |
| `EDGE_TTS_DOCKER_TESTS=1` | Docker и Compose | Docker и образ `edge-tts-mcp:local` |
| Обе переменные | В том числе синтез и подгонка в контейнере | Всё перечисленное выше |

Выбор групп: `uv run pytest -m live`, `uv run pytest -m "docker and not live"`
или `uv run pytest -m "docker and live"`. Покрытие: `uv run pytest --cov=edge_tts_mcp`.
Live-тесты используют только фиксированные тестовые фразы. Из-за особенностей
кодеков подгонка может выйти за допуск; такой результат должен сопровождаться предупреждением.

## Структура проекта

```text
edge_tts_mcp/
    __init__.py
    __main__.py
    config.py           # настройки и проверка ENV
    core/
        cli.py          # точка входа
        server.py       # MCP-инструменты
        service.py      # синтез и публикация файлов
        audio.py        # FFmpeg, FFprobe и проверка аудио
        timings.py      # тайминги и субтитры
tests/
Dockerfile
compose.yaml
.env.example
```

`edge-tts-mcp`, `python -m edge_tts_mcp` и `python main.py` используют одну
точку входа: `edge_tts_mcp.core.cli:main`.
