# edge-tts-mcp

Асинхронный MCP-сервер синтеза речи Microsoft Edge с транспортом stdio.
Создаёт MP3, OGG/Opus, субтитры SRT/WebVTT и JSON с таймингами слов.
При успешной генерации создаётся аудиофайл; субтитры и тайминги добавляются по запросу.

Требуется Python 3.12+. Для MP3 и субтитров без подгонки длительности FFmpeg не нужен.
Для OGG/Opus нужен FFmpeg с поддержкой libopus.
Для подгонки длительности нужны FFmpeg и FFprobe.
Текст отправляется в онлайн-сервис Microsoft; офлайн-режима нет.

## Структура

```text
main.py                 # запуск из корня проекта
edge_tts_mcp/
    __init__.py         # версия пакета
    __main__.py         # запуск через python -m edge_tts_mcp
    config.py           # встроенные значения, ENV и проверка конфигурации
    core/
        __init__.py
        cli.py          # аргументы CLI и запуск сервера
        server.py       # MCP-инструменты
        service.py      # синтез и публикация файлов
        audio.py        # проверка аудио, FFmpeg и FFprobe
        timings.py      # тайминги слов и формирование субтитров
Dockerfile
compose.yaml
tests/
pyproject.toml          # метаданные пакета и настройки разработки
requirements.txt        # прямые зависимости с фиксированными версиями
.env.example            # необязательный шаблон ENV без секретов
```

Все способы запуска используют одну функцию `edge_tts_mcp.core.cli:main`:
`python main.py`, `python -m edge_tts_mcp` и установленная команда `edge-tts-mcp`.

## Установка и запуск

Через `uvx`:

```sh
uvx --python 3.12 --from git+https://github.com/MrEnd3y/edge-tts-mcp.git edge-tts-mcp
```

Установка из локальной копии репозитория:

```sh
python -m pip install .
edge-tts-mcp
```

`uvx` устанавливает Python-зависимости, но не системные FFmpeg/FFprobe.
Транспорт — stdio; процесс сервера запускается MCP-клиентом.

## Подключение MCP

Пример конфигурации клиента:

```json
{
  "mcpServers": {
    "edge-tts-mcp": {
      "command": "uvx",
      "args": ["--python", "3.12", "--from", "git+https://github.com/MrEnd3y/edge-tts-mcp.git", "edge-tts-mcp"]
    }
  }
}
```

Для установленного пакета используйте `"command": "edge-tts-mcp"` без аргументов.
Настройки передаются через `env`; при необходимости укажите абсолютный путь к команде.
Таймаут MCP-клиента должен быть больше таймаута инструмента, например 60 секунд
при стандартном лимите синтеза 45 секунд.

## Инструменты

### `get_capabilities()`

Возвращает форматы, наличие исполняемых FFmpeg/FFprobe, ограничения, настройки голоса,
профили и доступность субтитров и таймингов. Сетевых запросов не делает.
Наличие FFmpeg не гарантирует поддержку libopus.

### `list_voice(locale="", gender="", query="", offset=0, limit=null)`

Без аргументов возвращает все голоса. `locale` фильтрует по префиксу без учёта
регистра (`ru`, `ru-RU`, `en`), `gender` принимает `Female`, `Male` или пустую строку.
`query` ищет по метаданным, `offset` и `limit` задают страницу результатов.
Поле `ShortName` из ответа передаётся в `tts.voice`.
Сетевой запрос ограничен 30 секундами; ошибка не маскируется пустым списком.

### `tts`

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `text` | обязательный | Непустой текст, до 100000 символов |
| `voice` | настройка сервера | Изначально `ru-RU-SvetlanaNeural` |
| `rate` | настройка или профиль | Скорость, например `+15%` |
| `volume` | настройка или профиль | Громкость, например `-10%` |
| `pitch` | настройка или профиль | Высота, например `+5Hz` |
| `audio_format` | `mp3` | `mp3` или `ogg` |
| `subtitles` | `none` | `none`, `srt` или `vtt` |
| `word_timings` | `false` | Сохранять JSON с таймингами слов |
| `profile` | `default` | `default`, `narration`, `notification`, `slow` |
| `timeout` | ENV или `45` | Бюджет выполнения: больше 0, не больше 300 секунд |
| `max_audio_duration_seconds` | ENV или `300` | Предел длины готового клипа: конечное число секунд > 0, независимо от `timeout` |
| `target_duration_seconds` | `null` | Желаемая длина клипа: конечное число > 0, не больше `max_audio_duration_seconds` |
| `tempo_min` | ENV или `0.5` | Минимальный допустимый темп подгонки, число от 0.5 до 2.0 |
| `tempo_max` | ENV или `2.0` | Максимальный допустимый темп подгонки, число от 0.5 до 2.0; не меньше `tempo_min` |

Обычное аудио:

```json
{"text": "Привет! Проверка синтеза речи."}
```

Аудио OGG/Opus и субтитры:

```json
{"text": "Привет, мир!", "audio_format": "ogg", "subtitles": "vtt"}
```

Аудио и тайминги слов:

```json
{"text": "Привет, мир!", "word_timings": true}
```

Тайминги соответствуют созданной озвучке с выбранным голосом и скоростью.
Это не распознавание существующей записи и не выравнивание по стороннему аудио или видео.

Подгонка длительности MP3 или OGG/Opus (требует FFmpeg и FFprobe):

```json
{"text": "Привет, мир!", "target_duration_seconds": 1.5, "tempo_min": 0.8, "tempo_max": 1.25, "subtitles": "srt", "word_timings": true}
```

Без цели или с `null` подгонка не выполняется: `tempo_min`/`tempo_max`
не меняют скорость, FFprobe не вызывается и поля подгонки не добавляются в ответ.
Независимый предел `max_audio_duration_seconds` действует и без цели.
После штатного синтеза с целью
измеряется оригинальный MP3 и вычисляется `tempo = original / target`.
Встроенный диапазон по умолчанию — **0,5–2,0**. AI-агент может
выбрать другой диапазон для задачи через `tempo_min` и `tempo_max`, но только
в технических границах сервера **0,5–2,0**. Параметры должны быть конечными числами,
`tempo_min <= tempo_max` (равенство разрешено); строки, `null` и булевы значения не подходят.
Для более осторожного изменения речи задайте, например, 0,85–1,15 через ENV
или параметры вызова. Больший допустимый диапазон не гарантирует качества речи.
FFmpeg `atempo` замедляет или ускоряет запись, не обрезает речь и не добавляет тишину.
За пределами выбранного диапазона возвращается `success: false`,
`error_code: "target_duration_unreachable"` и поля `required_tempo`, `tempo_min`,
`tempo_max`, `source_duration`, `target_duration` (длительности в секундах), без аудиофайла.
Сервер не расширяет диапазон автоматически. Агент может явно повторить запрос
с другими границами, не выходя за 0,5–2,0.
Если отношение переполняется, `required_tempo` равен `null` (цель всё равно недостижима).
После обработки длительность проверяется **FFprobe**. Даже при темпе 1,0 итог
проверяется, но перекодирование MP3 пропускается.
Допуск — **max(0,05 секунды, 1% цели)**.
Это лишь подгонка длительности клипа в заданных пределах, а не гарантия
естественной речи, идеальной синхронизации или выравнивания отдельных слов с видео.

При заданной достижимой цели ответ дополнительно содержит `duration_fitting`:
`target_duration_seconds`, `original_duration_seconds`, `requested_tempo`,
`applied_tempo`, `processed`, `tempo_min`, `tempo_max`,
`actual_duration_seconds`, `tolerance_seconds`, `target_met`.
`duration_seconds` всегда описывает готовый файл (округлённо до миллисекунд).
При заданной достижимой цели поле `tempo` верхнего уровня содержит фактически
применённый темп (1,0 при отсутствии изменения); оно совпадает с `applied_tempo`.
`success: true` означает наличие аудио, **не** достижение цели: проверяйте
`target_met` и `warnings` (`duration_target_not_met`, `duration_mismatch`).
При ошибке обработки или невалидном результате возвращается исходная речь
с предупреждением, если её удалось сохранить в запрошенном формате.
Отсутствие необходимого FFmpeg/FFprobe возвращает понятную `audio_error`.
Если проверить длительность возвращаемого файла не удалось, запрос завершается
ошибкой `audio_error`, а не сообщает об успешной подгонке.

Тайминги слов пересчитываются как `round(old_time_ms / applied_tempo)`;
SRT/VTT создаются по ним. Некорректные, схлопнувшиеся или выходящие за границы
клипа события не публикуются; аудио возвращается с `timing_metadata_unavailable`.
Подгонка и FFprobe входят в общий `timeout`, но он не ограничивает длину клипа.
Например, `timeout=60` и `max_audio_duration_seconds=600` означают максимум минуту
на выполнение и максимум десять минут готового аудио. Обработка может не успеть
за минуту. Предел цели определяется `max_audio_duration_seconds`, а не таймаутом.
Если готовый файл превышает предел, возвращается `audio_duration_exceeded`
без публикации файлов. Речь не обрезается. Предел проверяется и без цели.

Успешный ответ содержит `success: true` и `path` к основному файлу:

- Всегда: `audio_path`, `size`, `duration_seconds`, `format`, `mime_type` — данные аудиофайла.
- С субтитрами: `subtitle_path`, `subtitle_format`.
- С таймингами: `word_timings_path`, `word_count`. JSON содержит объекты
  `{"word": "Привет", "start_ms": 100, "end_ms": 500}`.

По умолчанию создаётся только аудио. Субтитры и тайминги появляются по запросу.
Если события слов отсутствуют или некорректны, запрос возвращает аудио
и предупреждение `timing_metadata_unavailable`. Пустые субтитры и выдуманные
тайминги не публикуются.
Слова группируются в короткие фразы; пунктуация и написание могут быть
нормализованы сервисом. Субтитры не встраиваются в видео.

Профиль `default` использует настройки сервера. `narration` задаёт скорость `-10%`,
`notification` — `+15%`, `slow` — `-25%`, с нейтральной громкостью и высотой.
Явные параметры вызова перекрывают профиль. Профили не меняют голос и не задают эмоции.

Таймаут включает очередь, синтез, конвертацию и запись результатов.
Длинный текст разбивается библиотекой с сохранением сквозных смещений.
Для него увеличьте таймаут инструмента и клиента; лимит 100000 символов
не гарантирует завершения за 300 секунд.

Ошибки возвращают `success: false`, `error_code` и `error`.
Коды: `invalid_input`, `timeout`, `no_audio`, `audio_error`, `io_error`,
`service_error`, `feature_disabled`, `target_duration_unreachable`, `audio_duration_exceeded`.
Нарушение MCP-схемы аргументов возвращается как ошибка инструмента.

## Настройки

| Переменная окружения | По умолчанию | Аргумент CLI |
| --- | --- | --- |
| `EDGE_TTS_OUTPUT_DIR` | `~/.edge-tts-mcp/output` | `--output-dir` |
| `EDGE_TTS_FFMPEG` | `ffmpeg` в PATH | `--ffmpeg` |
| `EDGE_TTS_FFPROBE` | `ffprobe` в PATH | `--ffprobe` |
| `EDGE_TTS_TEMPO_MIN` | `0.5` | — |
| `EDGE_TTS_TEMPO_MAX` | `2.0` | — |
| `EDGE_TTS_TIMEOUT_SECONDS` | `45` | — |
| `EDGE_TTS_MAX_AUDIO_DURATION_SECONDS` | `300` | — |
| `EDGE_TTS_VOICE` | `ru-RU-SvetlanaNeural` | `--voice` |
| `EDGE_TTS_RATE` | `+0%` | — |
| `EDGE_TTS_VOLUME` | `+0%` | — |
| `EDGE_TTS_PITCH` | `+0Hz` | — |
| `EDGE_TTS_ALLOW_SIDECARS` | `1` | `--disable-sidecars` запрещает субтитры/тайминги |
| `EDGE_TTS_MAX_CONCURRENT` | `2`, диапазон 1–16 | `--max-concurrent` |

Все значения читает и проверяет `edge_tts_mcp/config.py` при запуске.
Для индивидуальных настроек приоритет: **параметры MCP → ENV → встроенные значения**.
Пропуск границы темпа наследует её из ENV независимо от другой границы;
получившаяся пара всё равно должна удовлетворять `min <= max`.
`get_capabilities` показывает эффективные значения по умолчанию; числовые
значения также отражаются в MCP-схеме.
Профиль речи по-прежнему может задавать rate/volume/pitch, а явные параметры их перекрывают.

`tempo_min`/`tempo_max` — конечные числа в абсолютных границах 0,5–2,0.
Эти технические границы заданы в `config.py` и не расширяются через ENV или MCP.
Таймаут — конечное число > 0 и <= 300; максимальная длина аудио — отдельное
конечное число > 0 (не ограничено 300 секундами). Это значения по умолчанию,
которые агент может явно переопределить для конкретного запроса.

Директория сохранения, исполняемые файлы, разрешение sidecar-файлов и параллелизм —
серверные настройки, не аргументы `tts`. CLI переопределяет соответствующие ENV.
Файлы `.env` автоматически не загружаются и не требуются: сервер работает
со встроенной конфигурацией сразу после установки. Это исключает зависимость
от рабочей директории MCP-клиента. `.env.example` — только шаблон без секретов.
Обычно настройку передают через `env` в конфигурации MCP-клиента.
При желании создайте собственный `.env` по шаблону и явно загрузите его лаунчером:

```sh
uv run --env-file .env python -m edge_tts_mcp
```

Булевы настройки принимают `1/0`, `true/false`, `yes/no`, `on/off`.
Неверные настройки останавливают запуск с кодом 2 и понятной ошибкой в stderr
без значения переменной и без traceback. Наличие FFmpeg/FFprobe проверяется
только для операций, которым они необходимы, а не при старте.

Пути в ответе относятся к машине MCP-сервера. Сервер создаёт файлы локально,
не воспроизводит их и никуда не загружает. Готовые файлы остаются до удаления
пользователем. Временные файлы удаляются при обычных ошибках и отмене запроса.
Каждый файл публикуется атомарно; набор файлов не является транзакцией
при аварийном завершении процесса. Новые каталоги на POSIX создаются с правами
`0700`, готовые файлы — `0600`; на Windows действуют наследуемые ACL.

## Docker

Сборка из корня проекта:

```sh
docker build -t edge-tts-mcp:local .
docker run --rm edge-tts-mcp:local --version
docker run --rm --init -i -v speech-output:/data/output edge-tts-mcp:local
```

Или через Compose:

```sh
docker compose build
docker compose run --rm -T edge-tts-mcp
```

Compose передаёт настройки голоса, скорости, громкости, высоты, tempo, таймаута, длины клипа,
sidecar-файлов, параллелизма и исполняемых файлов из ENV процесса или своего
необязательного `.env`. Например, без `.env`:

```powershell
$env:EDGE_TTS_TEMPO_MIN = "0.85"
$env:EDGE_TTS_TEMPO_MAX = "1.15"
$env:EDGE_TTS_TIMEOUT_SECONDS = "60"
docker compose run --rm -T edge-tts-mcp
```

Либо передайте отдельный файл настроек явно:

```sh
docker compose --env-file /absolute/path/to/tts-settings.env run --rm -T edge-tts-mcp
```

Приоритет здесь: параметры `tts` → ENV контейнера (значения из окружения
лаунчера имеют приоритет над `.env` Compose) → встроенные значения.
Сервер сам `.env` не читает: файл загружает Docker Compose и передаёт только
переменные, перечисленные в `environment` файла `compose.yaml`.
При отсутствии переменной используется значение по умолчанию; явно пустая
переменная не скрывается за значением по умолчанию и проверяется сервером.

**Исключение для путей:** внутри Compose каталог вывода намеренно фиксирован
как `/data/output` и совпадает с точкой монтирования тома `speech-output`.
`EDGE_TTS_OUTPUT_DIR` из окружения хоста или общего `.env.example` не меняет этот
путь: Windows-путь/домашний каталог хоста нельзя автоматически использовать
в контейнере с read-only файловой системой. Для сохранения в конкретный каталог
хоста замените монтирование на bind mount (`/absolute/host/output:/data/output`),
не меняя путь внутри контейнера; проверьте права записи для UID контейнера.
`EDGE_TTS_FFMPEG` и `EDGE_TTS_FFPROBE`, если переопределены для Compose,
должны указывать на Linux-исполняемые файлы **внутри контейнера**, не на хосте.
Не подключайте весь `.env` через `env_file`: это может передать в контейнер
посторонние настройки и секреты.

MCP stdio запускается через `compose run --rm -T`, а не `compose up -d`:
MCP-клиент должен владеть stdin/stdout конкретного процесса.
На Windows MCP-клиенту может понадобиться наследование `ProgramFiles`, чтобы
Docker Desktop нашёл плагин Compose в ограниченном окружении дочернего процесса.

Контейнер содержит FFmpeg и FFprobe и работает от непривилегированного пользователя.
Для stdio используйте `-i` без `-t`; сетевых портов нет.
Результаты в примере сохраняются в именованном томе.
Для доступа с хоста используйте bind mount и учитывайте отображение путей:
возвращаемый `/data/output/...` — путь внутри контейнера.
При необходимости задайте `APP_UID` и `APP_GID` при сборке под владельца каталога хоста.

## Разработка

В виртуальном окружении установите проект и инструменты разработки:

```sh
python -m pip install -e . --group dev
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m bandit -q -r edge_tts_mcp
python -m pytest -q --cov=edge_tts_mcp
python -m pip wheel --no-deps --wheel-dir dist .
```

Опция `--group` требует pip 25.1+. Вместо pip можно использовать
`uv pip install -e . --group dev` с выбранным виртуальным окружением.
FFmpeg для офлайн-тестов поставляется отдельной тестовой зависимостью.
Интеграционные тесты подгонки используют также системный FFprobe (либо путь
из `EDGE_TTS_FFPROBE`); без него эти тесты пропускаются. Остальные проверки FFprobe — с моками.
Обычный запуск тестов не обращается к Microsoft и не требует Docker.

Проверки настоящего сервиса включаются явно, например в PowerShell:

```powershell
$env:EDGE_TTS_LIVE_TESTS = "1"
python -m pytest -q -m live -k "not long_text and not container"
Remove-Item Env:EDGE_TTS_LIVE_TESTS
```

Тесты контейнера требуют собранного образа и запущенного Docker:

```powershell
$env:EDGE_TTS_DOCKER_TESTS = "1"
python -m pytest -q -m "docker and not live"
Remove-Item Env:EDGE_TTS_DOCKER_TESTS
```

Реальный синтез и подгонка внутри контейнера (после сборки образа):

```powershell
$env:EDGE_TTS_DOCKER_TESTS = "1"
$env:EDGE_TTS_LIVE_TESTS = "1"
python -m pytest -q -m "docker and live"
Remove-Item Env:EDGE_TTS_LIVE_TESTS
Remove-Item Env:EDGE_TTS_DOCKER_TESTS
```

На самой машине live-тесты подгонки (`tests/test_live_duration.py`) требуют
доступного FFprobe: установите его в PATH или задайте `EDGE_TTS_FFPROBE`.
Без него обычные сетевые тесты синтеза выполняются, а live-проверки подгонки
пропускаются. Все live-тесты отправляют только фиксированные тестовые фразы.

Для полного прогона без пропусков нужны Docker с собранным образом, доступ к
Microsoft и локальный FFprobe. Включите оба флага выше, задайте при необходимости
`EDGE_TTS_FFPROBE` абсолютным путём к исполняемому файлу и выполните
`python -m pytest -q --cov=edge_tts_mcp` без фильтра `-m`.
