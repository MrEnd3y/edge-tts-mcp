# edge-tts-mcp

Асинхронный MCP-сервер синтеза речи Microsoft Edge с транспортом stdio.
Создаёт MP3, OGG/Opus, субтитры SRT/WebVTT и JSON с таймингами слов.
Возвращает локальные пути к файлам. Воспроизведение, отправку и загрузку выполняет клиент.

## Требования

- Python **3.12+** для запуска без Docker.
- Доступ к сервису Microsoft: синтез выполняется онлайн, текст передаётся сервису.
- Для OGG/Opus — FFmpeg с `libopus`.
- Для изменения темпа MP3 — FFmpeg с `libmp3lame`; для проверки целевой длительности — FFprobe.

MP3 без изменения длительности не требует FFmpeg. Субтитры и тайминги сами по себе
не добавляют требований к FFmpeg. Docker-образ включает Python, FFmpeg и FFprobe.

## Установка и запуск

Через `uvx`:

```sh
uvx --from git+https://github.com/MrEnd3y/edge-tts-mcp.git edge-tts-mcp
```

Установка из локальной копии репозитория в выбранное Python-окружение:

```sh
python -m pip install .
edge-tts-mcp
```

`uvx` устанавливает Python-зависимости, но не системные FFmpeg/FFprobe.

## Подключение MCP

Пример для клиентов с форматом конфигурации `mcpServers`:

```json
{
  "mcpServers": {
    "edge-tts-mcp": {
      "command": "uvx",
      "args": [
        "--from",
        "git+https://github.com/MrEnd3y/edge-tts-mcp.git",
        "edge-tts-mcp"
      ]
    }
  }
}
```

Для установленного пакета используйте `"command": "edge-tts-mcp"`.
Параметры запуска необязательны и передаются в `args`, например:
`"args": ["--voice", "en-US-AriaNeural", "--max-concurrent", "4"]`.
При запуске через `uvx` эти флаги добавляются **после** `edge-tts-mcp`;
параметры самого `uvx`, такие как `--from`, указываются перед именем команды.
Настройки передаются через `env`; при необходимости укажите абсолютный путь к команде.
MCP-клиент запускает сервер как дочерний процесс и работает с его stdin/stdout.
Таймаут MCP-клиента должен быть больше таймаута инструмента, например 60 секунд
при стандартном лимите синтеза 45 секунд.

## Инструменты

### `get_capabilities()`

Возвращает форматы, наличие исполняемых FFmpeg/FFprobe, ограничения, настройки голоса
и доступность субтитров и таймингов. Сетевых запросов не делает.
Проверяется наличие исполняемых файлов, а не поддержка конкретных кодеков.

### `list_voice`

Без аргументов возвращает все голоса. `locale` фильтрует по префиксу без учёта
регистра (`ru`, `ru-RU`, `en`), `gender` принимает `Female`, `Male` или пустую строку.
`query` ищет по названиям, языку и тегам голоса; `offset` и `limit` задают страницу результатов.
По умолчанию: `locale=""`, `gender=""`, `query=""`, `offset=0`, `limit=null`.
`offset` — целое число >= 0; `limit` — целое число 1–1000 либо `null` без ограничения.
Поле `ShortName` из ответа передаётся в `tts.voice`.
Запрос к Microsoft ограничен 30 секундами. При сбое инструмент возвращает ошибку.

### `tts`

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `text` | обязательный | Непустой текст, до 100000 символов |
| `voice` | настройка сервера | Изначально `ru-RU-SvetlanaNeural` |
| `rate` | настройка сервера | Скорость, например `+15%` |
| `volume` | настройка сервера | Громкость, например `-10%` |
| `pitch` | настройка сервера | Высота, например `+5Hz` |
| `audio_format` | `mp3` | `mp3` или `ogg` |
| `subtitles` | `none` | `none`, `srt` или `vtt` |
| `word_timings` | `false` | Сохранять JSON с таймингами слов |
| `timeout` | ENV или `45` | Максимальное время выполнения запроса в секундах: `0 < timeout <= 300` |
| `max_audio_duration_seconds` | ENV или `300` | Максимальная длительность аудио в секундах: конечное число > 0, независимо от `timeout` |
| `target_duration_seconds` | `null` | Целевая длительность аудио в секундах: конечное число > 0, не больше `max_audio_duration_seconds` |
| `tempo_min` | ENV или `0.5` | Минимальный коэффициент изменения скорости, от 0.5 до 2.0 |
| `tempo_max` | ENV или `2.0` | Максимальный коэффициент изменения скорости, от 0.5 до 2.0; не меньше `tempo_min` |

`voice`, `rate`, `volume` и `pitch` можно пропустить или передать как `null`
для использования настроек сервера. `rate` и `volume` — строки со знаком
и процентами (`+15%`, `-10%`), `pitch` — строка со знаком и Hz (`+5Hz`).
Числовые параметры `tts` передаются JSON-числами, не строками; среди них `null`
разрешён только для `target_duration_seconds`.
Если сохранение субтитров и таймингов отключено на сервере, запрос с ними
завершается `feature_disabled` без синтеза аудио.

**Обычное аудио:**

```json
{"text": "Привет! Проверка синтеза речи."}
```

**OGG/Opus с субтитрами и таймингами:**

```json
{"text": "Привет, мир!", "audio_format": "ogg", "subtitles": "vtt", "word_timings": true}
```

### Изменение длительности аудио

```json
{"text": "Привет, мир!", "target_duration_seconds": 1.5, "tempo_min": 0.8, "tempo_max": 1.25, "subtitles": "srt", "word_timings": true}
```

Если `target_duration_seconds` не задан или равен `null`, сервер не меняет скорость после синтеза:
`tempo_min`/`tempo_max` не применяются, FFprobe не вызывается,
поля `tempo` и `duration_fitting` не добавляются в ответ.
Ограничение длительности `max_audio_duration_seconds` действует и без цели.

После синтеза измеряется исходный MP3 и вычисляется `tempo = source_duration / target_duration`.
FFmpeg `atempo` изменяет скорость без обрезки речи и добавления тишины.
Диапазон по умолчанию и абсолютные технические пределы — **0,5–2,0**.
В запросе или ENV можно задать свой диапазон в этих пределах, например 0,85–1,15.
Границы должны быть конечными числами: `0.5 <= tempo_min <= tempo_max <= 2.0`.
Сервер не расширяет их автоматически.

Если требуемый темп вне выбранного диапазона, возвращается `success: false`,
`error_code: "target_duration_unreachable"` и поля `required_tempo`, `tempo_min`,
`tempo_max`, `source_duration`, `target_duration` (длительности в секундах), без аудиофайла.
Клиент может повторить запрос с другими допустимыми границами.
Если отношение переполняется, `required_tempo` равен `null` (цель всё равно недостижима).
Готовый файл проверяется **FFprobe** с допуском **max(0,05 секунды, 1% цели)**.
При темпе 1,0 MP3 не перекодируется, но итоговая длительность всё равно проверяется.
Если допуск не достигнут, проверенное аудио возвращается
с `duration_fitting.target_met: false` и предупреждением, если файл не превышает
`max_audio_duration_seconds`.
Длительность аудио изменяется только в заданных пределах. Это не гарантия
естественной речи, идеальной синхронизации или точного выравнивания отдельных слов.

### Ответ и предупреждения

Успешный ответ содержит `success: true`, `path` и `audio_path`, `size`,
`duration_seconds`, `format`, `mime_type`. Длительность относится к готовому файлу
и округляется до миллисекунд.
Также возвращаются `voice`, `rate`, `volume`, `pitch` и `characters`.

- С субтитрами: `subtitle_path`, `subtitle_format`.
- С таймингами: `word_timings_path`, `word_count`.
- С целью: `tempo` — фактически применённый темп, и объект `duration_fitting`.

Поля `duration_fitting`:
`target_duration_seconds`, `original_duration_seconds`, `requested_tempo`,
`applied_tempo`, `processed`, `tempo_min`, `tempo_max`,
`actual_duration_seconds`, `tolerance_seconds`, `target_met`.

`tempo` совпадает с `applied_tempo`; 1,0 означает отсутствие изменения скорости.
`processed` показывает, применено ли изменение скорости, а не обычная конвертация MP3 в OGG.
**`success: true` не гарантирует достижения цели**: проверяйте
`duration_fitting.target_met` и `warnings` (`duration_target_not_met`, `duration_mismatch`).
При ошибке обработки или невалидном результате возвращается исходная речь
с предупреждением, если её удалось сохранить в запрошенном формате.
Отсутствие необходимого FFmpeg/FFprobe возвращает понятную `audio_error`.
Если проверить длительность возвращаемого файла не удалось, запрос завершается
ошибкой `audio_error`, а не сообщает о достижении целевой длительности.

### Тайминги и субтитры

Тайминги берутся из событий Microsoft WordBoundary при синтезе речи,
а не определяются по готовому аудио. JSON содержит объекты вида
`{"word": "Привет", "start_ms": 100, "end_ms": 500}`.

При заданной цели времена пересчитываются как `round(old_time_ms / applied_tempo)`;
SRT/VTT создаются по проверенным данным. Временные отметки должны идти
по порядку, не перекрываться и не выходить за границы аудио
с округлением до миллисекунд. Без цели для конца последнего события допускается
расхождение с длительностью файла до 500 мс.
Если тайминги отсутствуют или не проходят проверку, файлы субтитров и таймингов не создаются;
аудио возвращается с предупреждением `timing_metadata_unavailable`.
Выдуманные тайминги не подставляются.
Слова группируются в короткие фразы; субтитры сохраняются отдельным файлом.

### Ограничения

`timeout` — максимальное время выполнения запроса в секундах. В него входят
ожидание в очереди, синтез, обработка и сохранение файлов.
`max_audio_duration_seconds` отдельно ограничивает длительность готового аудио.
Например, значения `60` и `600` означают 60 секунд на выполнение запроса
и не более 600 секунд аудио.
При превышении таймаута запрос прерывается; остановка FFmpeg/FFprobe
и очистка временных файлов могут потребовать дополнительного времени.
Если готовый файл превышает предел, возвращается `audio_duration_exceeded`
без сохранения готовых файлов. Речь не обрезается. Ограничение проверяется и без цели.

Длинный текст синтезируется частями. Лимит 100000 символов
не гарантирует завершения запроса за 300 секунд.

Ошибки возвращают `success: false`, `error_code` и `error`.
Коды: `invalid_input`, `timeout`, `no_audio`, `audio_error`, `io_error`,
`service_error`, `feature_disabled`, `target_duration_unreachable`, `audio_duration_exceeded`.
Нарушение MCP-схемы аргументов возвращается как ошибка инструмента.

## Настройки

| Переменная окружения | По умолчанию | Аргумент CLI |
| --- | --- | --- |
| `EDGE_TTS_OUTPUT_DIR` | `~/.edge-tts-mcp/output` | `--output-dir` |
| `EDGE_TTS_FFMPEG` | `ffmpeg` в PATH | `--ffmpeg` |
| `EDGE_TTS_FFPROBE` | `ffprobe` в PATH | `--ffprobe` |
| `EDGE_TTS_TEMPO_MIN` | `0.5` | — |
| `EDGE_TTS_TEMPO_MAX` | `2.0` | — |
| `EDGE_TTS_TIMEOUT_SECONDS` | `45` | — |
| `EDGE_TTS_RETRY_ATTEMPTS` | `5` | — |
| `EDGE_TTS_RETRY_INITIAL_DELAY_SECONDS` | `2` | — |
| `EDGE_TTS_RETRY_MAX_DELAY_SECONDS` | `10` | — |
| `EDGE_TTS_MAX_AUDIO_DURATION_SECONDS` | `300` | — |
| `EDGE_TTS_VOICE` | `ru-RU-SvetlanaNeural` | `--voice` |
| `EDGE_TTS_RATE` | `+0%` | — |
| `EDGE_TTS_VOLUME` | `+0%` | — |
| `EDGE_TTS_PITCH` | `+0Hz` | — |
| `EDGE_TTS_ALLOW_SIDECARS` | `1` | `--disable-sidecars` запрещает субтитры/тайминги |
| `EDGE_TTS_MAX_CONCURRENT` | `2`, диапазон 1–16 | `--max-concurrent` |

При временном сбое синтеза сервер повторяет тот же запрос до 5 попыток всего
(первая попытка включена): паузы растут вдвое от 2 секунд и ограничены 10 секундами.
Число попыток и интервалы задаются ENV-переменными выше; все попытки и ожидания входят
в `timeout`. Повторяются `no_audio`, ошибки WebSocket/сетевого соединения, таймаут,
HTTP 429 и 5xx.
Ошибки параметров и `target_duration_unreachable` не повторяются.
Если попытки исчерпаны, сервер возвращает ошибку. Менять текст и делать новый вызов
решает вызывающий агент.

При запуске сервера приоритет: **CLI → ENV → встроенные значения**.
Параметры конкретного запроса `tts` переопределяют соответствующие значения сервера.
Доступные CLI-флаги указаны в таблице; полный список — `edge-tts-mcp --help`.

Переменные окружения задаются в настройках MCP-клиента или при запуске сервера. `.env` необязателен
и не читается сервером автоматически; шаблон — `.env.example`.

## Docker

Контейнер включает Python, FFmpeg и FFprobe. Запуск из корня репозитория:

```sh
docker compose build
docker compose run --rm -T edge-tts-mcp
```

Настройки передаются через ENV или необязательный `.env` Compose.
Аудио сохраняется в том `speech-output`, внутри контейнера — `/data/output`.
Этот путь фиксирован в Compose и не меняется через `EDGE_TTS_OUTPUT_DIR` хоста.
Для доступа к файлам с хоста можно смонтировать его каталог вместо тома.

## Разработка

```sh
uv sync --group dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run bandit -q -r edge_tts_mcp
```

По умолчанию тесты не обращаются к Microsoft и не требуют Docker.
Тестовый FFmpeg входит в dev-зависимости; FFprobe нужен в PATH или через `EDGE_TTS_FFPROBE`.
Если его нет, интеграционные проверки изменения длительности пропускаются.

Дополнительные проверки включаются переменными окружения:

| Переменная | Проверки | Требования |
| --- | --- | --- |
| `EDGE_TTS_LIVE_TESTS=1` | Реальный синтез Microsoft | Сеть; для изменения длительности — локальный FFprobe |
| `EDGE_TTS_DOCKER_TESTS=1` | Docker и Compose | Docker и образ `edge-tts-mcp:local` |
| Обе переменные | В том числе синтез и изменение длительности в контейнере | Всё перечисленное выше |

Выбор групп: `uv run pytest -m live`, `uv run pytest -m "docker and not live"`
или `uv run pytest -m "docker and live"`. Покрытие: `uv run pytest --cov=edge_tts_mcp`.
Live-тесты используют только фиксированные тестовые фразы. Из-за особенностей
кодеков итоговая длительность может выйти за допуск; такой результат должен сопровождаться предупреждением.

## Структура проекта

```text
main.py
edge_tts_mcp/
    __init__.py
    __main__.py
    config.py           # настройки и проверка ENV
    core/
        __init__.py
        cli.py          # точка входа
        server.py       # MCP-инструменты
        service.py      # синтез и публикация файлов
        audio.py        # FFmpeg, FFprobe и проверка аудио
        timings.py      # тайминги и субтитры
tests/
Dockerfile
compose.yaml
pyproject.toml
.env.example
```

`edge-tts-mcp`, `python -m edge_tts_mcp` и `python main.py` используют одну
точку входа: `edge_tts_mcp.core.cli:main`.
